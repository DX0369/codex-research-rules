# 更新科研项目状态

## 原则

- 用户要求记录进展时，更新项目根目录下已有的 `PROJECT_STATE.md`，并保持其中文语言和现有组织方式。用户明确要求整理项目接手入口时，在授权范围内更新相关说明和已有历史资料。
- 不创建缺失文档；缺失时停止并建议用户使用 `init-research-project-docs` Skill。
- 只写入用户明确确认，或由本轮工具证据直接确认的事实。不得把计划、推测或旧聊天记忆写成
  已完成状态。
- 修改范围以本轮授权的文档为准。
- 保持更新简洁，不复制完整日志、配置或长篇分析。

## 更新流程

1. 读取现有 `PROJECT_STATE.md`，了解其当前结构、已有实验标识、术语和最新状态。
2. 收集本轮已经确认的新事实，并区分：正式结果、初步观察、失败或部分完成、未知信息、研究
   决策和下一步。
3. 若要写入的实验状态尚未被可靠确认，停止并说明缺失证据；需要检查真实运行状态时，先使用
   `audit-experiment-status` Skill。
4. 使用机器实际时间更新文档，至少精确到分钟并包含时区。
5. 以最小改动更新相关章节，避免重写无关历史、改变原有结论或重新设计文档结构。
6. 整理项目接手入口时，在 `PROJECT.md` 维护当前可用入口，已有 README 可以链接过去。已核验的进展写入 `PROJECT_STATE.md`，仍用于复现的旧协议及命令归入已有历史资料。检查文档间的引用和入口是否仍可定位。
7. 修改后检查状态是否自洽，确保同一任务的当前状态有明确证据。

## 记录规则

- 简要记录实验历程和关键结果。当前仍需定位的产物，以及已结束但仍用于论文、结论核对或复现的结果，优先用项目相对路径保留证据入口。
- 明确区分正式结论、初步观察、失败或部分结果和未知项。
- 结果不足以支持结论时，只记录观察及其限制，不提升为正式结论。
- 下一步只记录当前已经决定的行动；建议但未确认的行动放在待决定或未知项中。
- 不删除仍然有效的历史记录，不为了简洁覆盖此前科研结论。

## 完成报告

报告更新的文档和状态、所依据的事实、已核对的引用，以及仍缺证据的信息。
