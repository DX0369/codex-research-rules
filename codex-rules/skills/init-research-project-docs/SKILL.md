# 初始化科研项目文档

## 执行流程

1. 读取当前目录适用的 `AGENTS.md`。
2. 检查 `PROJECT.md` 和 `PROJECT_STATE.md` 是否存在：
   - 两者都存在时，不覆盖；报告位置并停止。
   - 仅缺少一个时，读取已有文档，并只创建缺失文档。
3. 只读检查现有 README、配置、主要代码目录及已有数据、模型和实验产物。只检查主要
   目录和浅层关系；大型数据和日志按照 `AGENTS.md` 有界读取。
4. 区分磁盘或文档支持的事实与未知信息，不推断研究目标、科学结论、环境、GPU、协议或
   实验状态。
5. 缺失信息会影响研究目标、科学语义、运行环境、正式协议或现有实验状态时，先询问用户。
6. 使用 `date '+%Y-%m-%d %H:%M %:z'` 获取机器实际时间，不估算时间。
7. 根据项目实际情况使用下列最小结构创建中文文档；允许省略无实际内容的可选部分，
   不得为填满格式而编造内容。
8. 报告创建的文件和仍待用户确认的信息，然后停止。

## `PROJECT.md`

使用以下最小结构，并根据实际项目调整：

```markdown
# 项目说明

更新时间：YYYY-MM-DD HH:mm +08:00

## 研究目标

说明项目要回答的问题及当前边界。

## 项目组织

简要说明代码、数据、模型和实验产物如何组织，只记录主要目录和浅层关系。

## 运行环境与约定

记录已经确认的机器、环境、GPU、后台运行、实验跟踪、本地服务约定和项目实际采用的实验协议。
```

不要复制完整 README、配置、命令、日志或文件树；已有权威来源时简要说明其位置。

## `PROJECT_STATE.md`

使用以下最小结构，并根据当前研究状态调整：

```markdown
# 项目状态

更新时间：YYYY-MM-DD HH:mm +08:00

## 当前重点

说明当前研究问题、所处阶段和本轮目标。

## 当前实验状态

简要记录当前正在运行、刚完成、失败或等待处理的实验。只有当前需要直接定位的结果可以
记录项目相对路径，不记录机器相关的绝对路径。

## 实验历程

按时间简要记录对研究推进有意义的实验或实验轮次，包括实验名称或标识、目的或主要变化、
状态、简要结果及其对研究判断的影响。不记录完整命令、长日志或历史产物路径。

## 当前结论

### 已确认

记录由正式实验支持的当前结论。

### 初步观察

记录仅由 smoke、diagnostic、少量样本或 partial 实验支持的现象。

### 尚未确认

记录仍需实验回答的问题。

## 下一步

按优先级记录少量明确任务。
```

## 状态记录规则

- 正文、标题和状态说明全部使用中文；文件名保持为 `PROJECT.md` 和 `PROJECT_STATE.md`。
- 文档更新时间和新实验历程时间至少精确到分钟并包含时区，使用机器实际时间。
- 历史实验只有在日志、状态文件或产物中存在可靠时间证据时才记录具体时间；证据不足时
  标记时间未确认，不根据文件名、文件修改时间或对话记忆推断。
- 实验历程只记录影响研究判断的实验或轮次，不记录普通阅读、格式修改、静态检查等动作。
- Smoke 只有在发现会改变实现或实验设计的重要问题时才写入实验历程。
- 历史实验记录不维护产物路径。当前仍需访问的结果只在“当前实验状态”中记录项目相对
  路径；目录整理后只更新当前状态，不批量改写历史记录。
- 明确区分 completed、running、partial、failed 和 repaired，不把计划写成完成，不把
  smoke、diagnostic、partial 或 failed 结果写成正式结论。

## 禁止事项

- 不修改代码、数据、模型、配置、实验产物或现有项目文档。
- 不启动测试、smoke、训练、评测、推理或数据生成。
- 不重组目录，不创建两个目标文档之外的说明文件。
- 不以聊天记录替代磁盘证据，不自行补全未知信息。
