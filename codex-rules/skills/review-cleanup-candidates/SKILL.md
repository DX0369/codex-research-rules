# 审查清理候选

1. 按用户指定范围只读盘点。核对主线入口、引用、Git 状态、活跃作业、历史复现需求。共享目录或符号链接涉及实际归属时，先检查文件类型、属主和使用方。
2. 对一次性代码、数据、配置、产物和非主线内容，判断是否仍用于运行、诊断或复现。需要留下的结论、生成来源或原始证据写入保留项。重复或过时文档说明合并到哪份现有资料，并核对仍使用的引用。
3. 评估 SHA 校验、门控和防御性测试所防的实际错误。已有等价覆盖或缺少具体用途时，说明如何精简。保留能防实际回归的最小覆盖。
4. 按路径交付建议动作、证据、保留内容和验收方式。提交按可独立理解和回退的改动组织，给出范围和建议提交说明。用户只要求计划时以清单为交付。需要执行时，按已授权范围改动并用相关入口或现有用例验收。
