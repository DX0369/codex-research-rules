# 科研工程规则

## 项目信息与任务授权

- 每个具体科研子项目应在自己的目录下维护 `PROJECT.md` 和 `PROJECT_STATE.md`。具体科研子项目通常是某个方法、数据集、实验系统或复现对象的代码目录。收纳多个子项目的父目录统一用 `README.md` 导航。子项目自身有上手说明需求时可加 README。补充文档优先复用已有位置，有明确的独立用途或用户要求时再单独创建。
- `PROJECT.md` 用中文简要记录研究目标、代码与运行入口、数据、模型、实验产物、运行环境和已确认的项目约定。目录结构只记录主要目录和浅层关系。`PROJECT_STATE.md` 用中文记录当前阶段、实验状态、简要实验历程、已有结论、待解决问题和下一步。仅在这些内容发生实质变化时更新，同一轮可合并记录一次。只读任务不自动更新。
- 两个文档的更新时间和新实验记录使用机器实际时间，至少精确到分钟并包含时区。实验历程可简要记录结果。当前仍需定位的产物，以及已结束但仍用于论文、结论核对或复现的结果，优先在 `PROJECT_STATE.md` 用项目相对路径保留证据入口。
- 涉及科研目标、实验协议、资产路径或实验状态时，先读相关项目文档并核对影响本次任务的信息。缺失或冲突的信息会影响任务范围、科学语义、正式运行协议、输入输出或不可逆操作时，询问用户。其他可逆实现细节遵循项目惯例，采用最简单方案。
- 用户只要求分析、解释、审查、审计或规划时，只检查相关材料并报告。用户要求实现、修复或构建时，在本轮授权范围内做局部修改及相关验证。
- 正式运行包括使用正式输入、协议和输出位置生成科研结果的训练、评测、推理、数据生成和统计。判断依据是结果的用途和执行协议。读取既有结果、核对覆盖和重复记录属于只读审计。按正式协议重新计算科研指标或生成新的科研统计结果，按正式运行管理。
- 正式运行默认由用户启动。用户只要求准备时，核对协议、环境、输入输出、资源门槛和必要验证，交付可复制命令与核验结果。用户明确授权 AI 启动本次运行时，确认这些条件满足后，在授权范围内执行。

## 主上下文保护与探索委托

- 主 Agent 保留当前任务状态、关键事实、精确证据、科研约束和最终判断。
- 按问题的独立性和信息压缩收益决定是否委托。大范围、跨模块或入口不明的调查，若边界清晰且能独立完成，可在主 Agent 大量读取前委托。提供目标、动机、范围、已知线索、科研约束和期望输出，权限沿用本轮授权。
- 对适合委托的大范围只读搜索、定位、提取、计数、筛选和简单监控，默认使用 `gpt-6-luna`，`reasoning_effort = "max"`。普通的解释、比较、规划或综合子任务，可沿用主 Agent 的模型和推理等级，由子 Agent 完成该问题所需的探索与分析。
- 对会改变研究路线、正式实验协议或主要结论，且证据仍难判断的问题，主 Agent 使用其他模型时，在适合独立复核的情况下优先委托 `gpt-6.2-astra`，`reasoning_effort = "max"`。主 Agent 已使用 `gpt-6.2-astra` 时，默认自行核对。关键证据仍冲突、确实需要独立第二意见，或用户明确要求复核时，可另做定向复核。向复核者提供必要证据和约束，请其查找反例、遗漏和可能改变判断的事实。
- 子 Agent 按互不重叠的问题分工，返回简明结论、证据位置、来源冲突、科研语义歧义、未知项和置信度。子 Agent 的权限限于委托范围，实验操作和再次委托由主 Agent 处理。
- 子 Agent 需要临时产物时，主 Agent 在任务说明中给出科研子项目 `tmp/` 的绝对路径。
- 委托后优先推进其余独立工作。证据不足时先定向追问。证据仍不足、关键事实冲突或证据位置不明确时，由主 Agent 定向复查。主 Agent 对最终判断负责，关键结论应有可定位的证据。工具或模型不可用时，由主 Agent 通过窄查询和定向读取完成必要核对。

## 语义正确性

- 按已确认的协议验证和处理失败。协议约束无法满足时，显式失败并保留可定位的错误和失败记录。
- 必填值从 canonical 字段名读取并按协议验证。不得使用默认值、字段别名、推断值、近似匹配、空值或其他字段的值进行替代。
- 区分值缺失与显式有效值，例如 `0`、`False`、空字符串或空集合。只有协议明确定义为可选的字段，才按可选字段处理。
- 科学方法中的 fallback 仅在方法或评测协议明确定义时使用。触发条件应具名、狭窄、可审计、可计数并经过验证。
- 可直接修复保持既定语义的明确语法或实现错误。修改协议规定的字段、数据、参数、指标、失败处理或实验流程前，须取得用户明确确认。

## 简单实现与 YAGNI

- 评估优化项时，先说明当前场景有什么问题、改动能解决什么。只影响未来场景的能力，按需要列为选项。
- 增加依赖或编写新实现前，先检查现有代码和已声明的依赖，优先复用合适且仍在维护的方案。选择满足当前需求、直接且易于阅读和修改的实现，改动限于本轮任务。需要扩展时，先确认最小端到端路径。
- 避免过度防御设计。按实际支持的输入、状态和失败情况编写代码，按约定处理错误。额外分支、重试、兜底、兼容层和配置层应有明确用途。组件按实际职责拆分，包装函数和扩展点按当前需要引入。
- 校验集中在数据输入、外部接口等边界。已由协议、类型或上游检查保证的条件，内部调用直接使用。增加 SHA 校验、门控等额外检查前，明确它要拦截的错误或保护的结果，并采用足以覆盖风险的最小检查。
- 只删除本次明确替换且已确认无需保留的旧实现。保留历史实验复现仍依赖的代码。

## 验证

- 验证强度与修改风险和影响范围相匹配。测试实际行为和科学不变量。修改影响共享行为或用户明确要求时，再扩大验证范围。
- 优先使用现有用例覆盖本轮改动。只有现有用例遗漏实际回归风险时，才补最小用例。样本数量以能回答验证问题为准。改动涉及必填字段时，验证字段缺失或值无效会显式失败。
- 正式运行前先检查已有测试、smoke 或实际运行记录。证据覆盖本次使用的入口和相关行为，且本轮改动没有使它失效时，直接引用。存在缺口时，只验证受影响的环节。需要确认真实链路能从输入走到关键输出时，再做有界、具代表性的 smoke。
- Smoke 使用独立临时输出位置。
- 改动影响实际入口时，用用户实际使用的入口、目标和最小代表性用例验收。
- 结果异常时，先依据具体执行证据调查，再判断原因。

## 资源下载与外部网络

- 单个文件超过 500 MB，或大小未知且可能超过此限时，AI 下载须经用户明确授权。需要用户手动下载时，提供来源、大小、保存路径和支持续传的命令。通过工具或子 Agent 下载同样遵循本轮授权。已有授权在其范围内持续有效。
- 通用基础模型默认下载到 `~/model/` 等个人共享目录。项目指定、训练或微调得到的模型及产物放在对应项目目录，并在项目文档记录实际路径和来源。
- 通用外部数据优先放在已有的个人数据目录。需要指定默认位置时，用 `<可写个人根>/dataset/<数据集名>/`。同一数据集确实需要并存多个版本时，再在下面建版本子目录。项目已有指定路径时沿用该路径。
- Hugging Face 模型优先使用 `HF_ENDPOINT` 镜像，在下载进程中临时清除代理。大型资源使用支持断点续传的工具。
- 安装依赖时，优先沿用执行环境已有的镜像。更换环境、启动入口或遇到下载异常时，按实际使用的工具核对 pip 的索引配置（包括 `PIP_INDEX_URL`），或 Conda 合并后生效的渠道。项目明确指定专用索引或渠道时，遵循项目配置。
- 作业需要访问网络时，在实际执行环境核对目标服务和代理是否可达。仅在需要代理的进程中启用代理。本地服务和集群内部通信按实际使用的地址通过 `NO_PROXY` 与 `no_proxy` 绕过代理。访问 vLLM 等本地服务时将 `localhost` 和 `127.0.0.1` 纳入绕过范围，必要时临时清除相关进程的代理变量。

## 实验规划与运行

- 选择下一步科研实验时，先说明已有结果支持哪些解释、还有什么分不清。优先选择能改变研究取舍的最小可比对照，说明什么结果会让下一步继续、调整或停止。
- 规划实验时，明确使用的数据版本、划分和样本范围，优先沿用已有的可比设置。需要调整时，说明哪些结果仍可直接比较。根据研究问题选择有代表性的数据、任务或模型，优先覆盖可能影响结论的差异，并按实际验证范围表述结论。
- Conda 环境、机器、GPU、路径和实验协议使用用户指定或项目文档确认的设置。
- 实验命令与 `screen`、`nohup`、`systemd-run` 等后台管理方式解耦。正式评测和长时间推理优先使用项目已有 launcher、调度器或 `systemd-run --user`，未使用这些方式时用 `setsid` 脱离当前终端。
- 正式训练使用 SwanLab。Project、workspace、run name、断点续跑和记录方式按项目文档或配置执行。必要信息不明确时向用户确认。

## 长任务与等待

- 用户要求落盘，或已授权的实施任务预计需要跨会话续接时，在 `tmp/<任务标识>/PLAN.md` 记录目标、验收条件、必要约束、步骤和下一步。任务结束后，有实质进展时先把已确认的进展、结果和必要证据链接更新到 `PROJECT_STATE.md`，再清理本轮已无后续用途的计划、草稿等一次性文档。
- 长时间任务优先由已有 launcher、调度器或 watcher 持有。确定性状态检查由脚本完成。
- 按预计耗时和工具限制有界等待，避免高频轮询。任务或工具会话仍在运行时，续等原任务。重连后先核对实际状态，避免重复启动。平台明确支持完成通知时，可等待完成或异常通知。

## 文件与实验产物

- 项目目录按需建立。通常用 `data/` 存项目专用数据，用 `model/` 存项目专用模型，用 `outputs/` 存实验产物，用 `tmp/` 存临时材料。已有项目沿用能清楚定位这些内容的结构。
- 读取非代码文件前先检查类型和大小。处理大型文件、数据集、生成产物、长日志或长 diff 时，先确定核对范围和规模，再按需使用 schema、计数、确定性样本、定向搜索、聚合统计和有限片段。
- 当前任务及其子 Agent 显式创建的临时文件、目录和中间分析产物，放在具体科研子项目根目录的 `tmp/` 下。使用 `mktemp`、`tempfile` 等工具时显式指定该目录。沙箱、解释器或外部工具自动生成且无法控制的临时产物按工具行为处理。
- 使用文件型 Unix 套接字的作业，在启动器中为每个作业或阶段分配独立的短通信目录，并在相关子进程启动前配置。新增或修改这条运行链路时，按框架拼接后的完整地址核对字节长度。项目 `tmp/` 路径过长时，通信可使用作业私有的短临时目录，日志和正式产物按项目约定保存。
- 修改 canonical 数据、模型权重、hidden states 分片、分数、指标、provenance、历史结果或实验输出，须有用户明确授权。适配新代码或 validator 时，优先按既有资产协议处理。
- 替换共用模型、数据或配置前，核对实际版本和正在使用它的任务。比较或续跑时，以实际读取的资产版本判断结果是否可比。保留复现所需版本，或足以重建的来源、变换规则和冻结样本清单。
- 每次运行使用独立输出目录。协议或运行发生变化时，使用不同标识和输出位置，保留历史结果。
- 只生成完成当前任务、复现实验和必要恢复所需的产物。清理前核对文件是否仍用于运行、诊断、复现或后续流程。清理一次性产物前，在已有记录中保留必要结论和依据。验证结束后，清理本轮生成且已无后续用途的一次性产物。失败证据保留到问题定位完成。
- 正式实验的最终结果、运行状态和中间产物分开保存。Shard、checkpoint、cache 和临时诊断文件集中放置。最终指标应有唯一、明确、可复核的来源。项目文档记录必要摘要和 canonical 产物位置。
- 正式实验默认只保留 `metadata/command.txt` 与 `metadata/run_status.json` 两个自动维护文件。额外 provenance 按用户要求或实际排障需要生成。

## 完成与报告

- 达到用户要求的验收标准并完成本轮临时产物收尾后停止。
- 只有实际运行和产物证据表明预期任务全部结束、输入覆盖符合协议、重复与失败记录已核对、正式结果完整且可追溯时，才报告实验完成。按证据区分运行中、部分完成、失败、已修复和已完成。Import、进程启动、dry run 和 smoke 分别报告各自的验证结果。
- 交付时说明修改、验证、实际运行、失败和待处理项。说明哪些结论已有证据，哪些仍是推测，以及正式产物是否已验收。
